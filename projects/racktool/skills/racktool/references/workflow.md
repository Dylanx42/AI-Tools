# 对话操作流程

## 开始

先确定输入路径、所需操作和输出目录。用户给了当前 XLSX 并要求分析/导出时无需再确认文件。
只在找不到文件、多个候选无法唯一对应或确实缺少业务参数时提问。文件上传到云端不能使
Mac 文件系统自动更新；使用当前执行环境提供的工具，不宣称已完成无法访问的本地同步或安装。

初次打开优先读取所有 Sheet 的分析，记录原顺序、每柜 U 轴方向、占用与异常。多个 Sheet
默认视为不同机房；其他说明/资产 Sheet 原版面导出保留，但不凭文件名猜成机柜。
如果业务不是“一 Sheet 一机房”，以用户明确给出的规则为准，不硬编码客户名字。

对陌生布局使用 analysis-package；默认不附原文件但仍含业务文字。生成纯布局 Profile 后
执行 validate、apply dry-run 并核对候选；识别方向存在混合时不能用统一方向 Profile 强行覆盖。

## 编辑

保留原始文件。业务工作副本和 SQLite、分析包、日志放在私有目录。复制原文件是交接操作，
所有单元格修改只通过 RackCore CLI。可以接收自然语言设备名，但在机房/机柜/完整设备文字
和当前 U 位里查找唯一对象，然后调用稳定 ID，不能以同名设备作为唯一键。

每次提交成功读取返回状态和新的项目状态；下一个操作基于最新 Hash、Mapping 和 ID。
按用户授权在工作副本执行，不要把 GUI 的待处理队列或旧会话描述当成已提交事实。

## 导出

默认保留原版面：`export --layout source`。原机房 Sheet 的业务 XML 不重新绘制，U 轴、位置、
合并、文字、颜色、尺寸、其他原始页和关系保持；只添加新位置表并扩展所需样式。
如果原来已有“设备位置表”，保留它，新生成表使用唯一名称；不要删除未知业务页。
保留原版面的对象不等于支持解析/编辑 Excel Shape 或宏，V1 仍只支持基于单元格的机柜。

标准导出：每个导入机房独立 Sheet，柜内保留原升序/降序，单列设备区。它会统一样式并压缩
空白版面，不宣称复制原样式。新建空项目默认一个“机柜图” Sheet 包含两排虚拟机柜。

设备位置表从第 1 行开始：序号、设备、机柜、U 位、高度（U）、机房、状态；ID 列默认隐藏。
多 U 显示 `21-22U`，单 U 显示 `21U`。不显示来源单元格，不附顶端三行说明。
按原机房順序、原机柜排布及柜内 U 轴的视觉方向排列。告警写在对话/记录里，不占用表头。

## 交付

用简短中文说明已执行的操作、实际成功/失败、原文件是否保持、异常与文件链接。
人工 Excel/WPS 检查仍包括合并边框、多行文字、过滤与打印；不能由测试数量证明 GUI 可用。
输出 SQLite 和日志只在需要继续编辑/复现时交接，常规用户主要接收 XLSX。
