# ADR-014: Skill 主入口、机房 Sheet 与原版面导出

- Status: Accepted
- Date: 2026-10-14（北京时间）
- Updates: Requirements FR-004 / FR-009、ROADMAP 的 GUI 发布门槛；延续 ADR-001/002/003/013。

## Context

用户本地验收报告 GUI 排序和缩放控件文字为空，明确停止用 GUI，改以 Skill/AI 对话操作。
新增真实私有图及旧导出对比显示：Parser 已识别混合方向，Exporter 却统一重画为 descending，
并将两个机房合成一个 Sheet。先前矩阵校验 U 位置，却没有核对导出方向与原始 Sheet。
设备位置表的前三行说明、分开的起止 U 和来源坐标也不适合交付。

## Decision

- 当前主使用入口改为独立 RackTool Skill，用户以自然语言查询/编辑/导出，Agent 调用 CLI。
  不修复或删除历史 GUI，标记本地可用性验收失败；GUI 不再是用户当前流程或 V1 必选门槛。
- 既有 RackCore/CLI 保持离线、确定性、不依赖模型。Skill 不直接改 Excel/SQLite，不复制 Parser。
  先读取事实并唯一定位；未知布局使用 Profile validate/dry-run；编辑先计划再提交，遵循已有授权，
  不为清楚且已授权的工作副本操作重复请求许可，不擅自覆盖原业务文件。
- 标准导出按原工作簿顺序为每个机房建立同名 Sheet，保留每柜独立 ascending/descending；
  标准版面统一单列设备区与样式，不宣称复制原始空白、颜色或坐标。新建项目保留“机柜图”虚拟页。
- 新增 `export --layout source`：一次源字节快照与项目 Hash 匹配，重扫核对稳定身份/位置后，
  保留所有原业务 worksheet 及关联 OOXML 部件，仅追加新设备位置页及必要样式。
  原工作簿部件不经 openpyxl 重新序列化；workbook/关系/content types 原 XML 仅追加节点，
  styles 原索引/扩展保留并添加新表样式。原页的公式、备注、链接、尺寸、打印设置与附加页保留。
- 原有同名位置表和 Table 不删除/覆盖；新页/表使用唯一名称。VBA/ActiveX 不在支持范围。
  保留未知对象的源部件不等于支持识别或编辑它们。
- 原版面导出拒绝缺失/过期源、未提交模型、无法保留的结构。先临时保存、重载、逐部件与样式
  校验，发布前再次核对源 Hash，最后原子替换独立目标；不静默降级、不修改原图和项目 SQLite。
- 设备位置表第 1 行为标题：序号、设备、机柜、U 位、高度（U）、机房、状态；内部 ID 隐藏。
  范围显示 `21-22U`、单 U 为 `21U`，去掉来源坐标及顶部三行说明，按柜内视觉方向排序。
- Skill 在绑定项目默认选原版面，在新建/明确标准化时选标准版面。GUI 历史导出使用标准模式。

## Validation / Limits

用最小双机房混合轴 fixture 证明旧基线两个回归失败；增加方向、Sheet、精简表、原部件/样式
扩展、元数据、同名页、缺失/过期源、未提交模型、并发源变化及 Safe Sync 后导出的测试。
所有 144 布局矩阵增加独立构造方向断言。新增真实私有文件核验独立于已有 Golden，不能将
机器核验计为新增人工 Golden。修正版 XLSX 的 Excel/WPS 人工外观和打印验收仍待用户完成。
