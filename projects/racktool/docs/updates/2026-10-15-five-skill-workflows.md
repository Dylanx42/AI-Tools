# 2026-10-15：五项 Skill 工作流

用户要求并行开发。五个子 Agent 分别负责安全编辑、位置表回导、布局适配、对话执行及独立审计，
最终由主任务集成 CLI/Core/技能说明与发布。架构及边界见 ADR-016。

## 行为

- conversation query/preview/apply：从名称/机房/U 定位，不要求用户输入内部 ID；有界查询空闲 U，
  签名绑定预览与当前文件状态，显式提交后重新读取/导出，保留稳定身份，支持新进程恢复。
- layout inspect/propose/check：解释陌生布局、生成/验证纯规则，低置信/歧义停止，导入锁定源 SHA。
- sync edit：已有设备可显式改高和跨机房移动，复用备份、预检、写后验证与恢复，普通 move 不隐式改高。
- position-table preview/apply：编辑新导出的位置表后回导；绑定项目与新建项目均支持整批校验提交。
  保留七列可见格式和隐藏 ID，通过版本化隐藏元数据拒绝旧项目或篡改的表。
- 增加无需 Qt 的 scripts/verify_skill_workflows.py，用合成双机房在独立进程验证全链路，
  支持 --runner 指向正式完整包，输出 report.json/events.json；它不等同实际软件的对话验收。

## 约束和待验收

回导仅接受本轮起新导出的表；旧包导出缺少元数据，需从当前 SQLite 重新导出。不能通过新增行、
删行或改状态来新增/删除设备。整表排序保留隐藏 ID；不能只排序可见列。U 范围和高度必须一致。
批量换位/互占源区域、目标设备区过窄、未知对象保真等情况保守拒绝。
固定坐标 Profile 暂为每 Sheet 一个机柜，异构多规则使用独立项目，不承诺任意 XLSX 自动识别。

实际 Codex CLI 已尝试，但云端 CODEX_HOME 下 installation_id 不可创建，启动报 EROFS，
未进入模型调用；没有改只读挂载或凭证路径。实际 Mac Codex/WorkBuddy/TRAE 加载与对话，以及
Excel/WPS 保存隐藏元数据/外观/打印的人工检查仍待本机执行。

验证包括模块回归、全套测试、私有原图副本的跨房改高与新导出回导检查、原图 SHA 保持、
独立包新进程/UTF-8/缺省依赖隔离。只报告实际执行的测试和发布结果，不累加重叠 focused 测试数量。

## 本轮真实副本证据

用户 1013 原图（2 个机房、59 柜、51 设备）在私有目录副本完成名称定位→只读预览→
跨机房移动并增加 1U、改名→重读查询→原版面/标准版面导出→位置表无变化读回。稳定 device_id
保持，原图 Hash 不变，过期导出拒绝，原版面导出的原 worksheet parts 字节与工作副本一致。

这次真实验证暴露 WPS workbook/styles 扩展以及命名样式基表 apply 开关的问题，已改为
原 OOXML 的局部补丁并验证样式索引。基表原字节保留，不采用生成器丢失开关的副本；
cellXfs 的开关语义保护继续执行。公开夹具另验证修改位置表后的跨房回导。真实文件、
含业务文字的计划、SQLite 和证据仅留 samples/private，不进入仓库或 Skill。

最终审计另修复“提交后标记/结果读取/锁清理异常被误报拒绝”：直接使用 Core 已验证的提交快照，
这些附属报告错误返回 applied + warnings，避免让 Agent 重复执行已成功的业务变更；三种故障注入均有回归。
