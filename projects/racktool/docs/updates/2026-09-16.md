# RackTool V0.5 进度更新（2026-09-16）

## 当前状态

RackTool V0.1～V0.5 的自动化门禁当前通过。开发成果已经整理到远端分支
`codex/racktool-gui-redesign`，但尚未合并 `main`。Microsoft Excel/WPS 实机检查、macOS 最终用户
作业验收和 Windows GUI 人工检查仍未完成，不能记为人工 PASS。

## 已完成内容

### V0.1 Reader

- 读取工作表、实际内容范围、合并单元格、行高、列宽和常见样式特征。
- 检测 U 轴、机柜候选、设备占位及来源单元格范围。
- 保留原始工作表顺序和可追溯 evidence，输出确定性结构化结果。

### V0.2 Profile

- 提供通用 YAML Profile 的加载、校验、匹配、应用和 dry-run。
- Profile 进入项目导入、SQLite 持久化和重新扫描生命周期。
- 错误、冲突、缺失或被篡改的 Profile 会拒绝执行，不会静默产生错误项目状态。

### V0.3 Identity 与 Mapping

- 建立稳定的 `rack_id`、`device_id`、Placement 和 SourceMapping。
- 改名、移动、交换、删除后重现及重新扫描使用多证据匹配。
- 身份证据矛盾、重复或不足时 fail closed，避免误复用设备身份。

### V0.4 Safe Sync

- 写回前执行源文件绑定、Hash 新鲜度、U 位边界、占用、Mapping 和合并区域检查。
- 采用恢复备份、临时写入、重载校验、原子替换和工作簿/SQLite 联合回滚。
- 对 comment、hyperlink、data validation、defined name 和 threaded comments 等高风险元数据执行保护性拒绝。
- GUI 的设备移动先进入待同步列表，只有顶部“同步更改”会提交事务。

### V0.5 本地 GUI

- 默认启动为空项目，不自动加载示例、测试数据或最近项目。
- 提供总览、机柜、设备和异常四个操作页面。
- 机柜列表支持拉伸、完整名称显示以及来源、自然名称和占用率排序。
- 设备页支持搜索、机柜、状态、高度及排序筛选，并限制一次物化的行数。
- 总览按源工作表的行列关系展示整体排布；单机柜页面显示 U 位和设备占用。
- Excel 单元格中的多行文字在机柜图、设备列表、详情和待同步列表中保留换行。
- 异常使用中文说明，并直接显示受影响的工作表和单元格/范围；没有单一位置时明确标为项目级问题。
- GUI 只调用 RackCore，不直接使用 `openpyxl` 写 Excel。

### Excel 导出

- 导出独立 `.xlsx`，固定包含“机柜图”和“设备位置表”两个 Sheet。
- 机柜图遵循源工作簿的 Sheet 顺序；每个源机柜排保持为一个导出排，并按原列顺序排列，不再每四柜强制换行。
- 设备文字保留原换行，合并的机柜标题和设备区域使用完整闭合外框。
- 设备位置表包含机柜、U 位、来源工作表和来源单元格，并支持 Excel 标题筛选。
- 公式样式文字按普通文本保存，导出拒绝覆盖源工作簿，并通过临时文件、重载验证和原子替换落盘。

### 本地数据与备份

- 项目 SQLite 和运行备份迁入操作系统 RackTool 应用数据目录，不再散落在源 Excel 旁边。
- Excel 恢复备份按每个工作簿最多 3 份、最长 30 天保留。
- 成功或成功回滚后的 SQLite 事务备份立即删除；异常中断残留最长保留 7 天。
- 应用启动或打开项目时机会式清理过期数据，不需要后台常驻服务。
