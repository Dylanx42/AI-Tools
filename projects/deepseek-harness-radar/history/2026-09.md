## 2026-09-08｜Delta

### 👀 官方 DeepSeek Harness `0.1.3-alpha.2`｜⭐⭐⭐⭐⭐
- 最新开发基线推进到 `0.1.3-alpha.2`；稳定候选线仍保留 `0.1.2-rc.1`，继续双线观察。
- alpha.2 重点改善 0.1.3 长会话打开、恢复、持续对话时的卡顿与内存占用，并修复 Web 断线后无法自动恢复等问题。
- continuable Subagent 控制面进一步增强：支持消息排队、编辑、删除、Steer 与停止操作；这推进了 Agent Runtime 的“运行中治理”，但 nested waiting/唤醒、one-shot interoperability 与 usage 回传仍未因此自动闭环。
- **判断**：0.1.3 从 alpha.1 的 Session 架构重构进入 alpha.2 的性能/控制面修整阶段，但还不能视为 contract 稳定。
- **成熟度**：Alpha；继续观察。

### 👀 Windows clean install / 原生依赖回归｜⭐⭐⭐⭐⭐
- `0.1.3-alpha.2` 的 JSONL persistence 依赖链新增并精确锁定 `fs-ext@2.1.1`；该包没有预编译二进制，安装脚本直接走 `node-gyp`。
- 已有干净 Windows 11 + Node 24 环境真实报告：没有 Visual Studio C++ Build Tools 时，`npm install -g @deepseek-ai/dsh@alpha` 会在 `fs-ext` 编译阶段失败并整体回滚；同机安装 `0.1.2-rc.1` 成功。
- 社区 Windows Desktop wrapper 已通过固定 Node ABI + 预编译 `fs-ext` 绕开现场编译，侧面说明平台 artifact / native dependency gate 已成为真实分发问题。
- **判断**：Compatibility gate 新增 **OS × Node ABI × native dependency × clean install**；不能只验证 Host boot 和插件 API。

### 🔥 MCP Runtime reliability｜`tools/list` 可被异常分页无限挂起｜⭐⭐⭐⭐½
- 今日公开报告在当前 npm 线（至 alpha.2）复验：MCP `syncTools` 会持续跟随服务端返回的 `nextCursor`，如果异常/恶意 MCP server 永不终止 cursor，Harness 缺少明确 page cap / deadline，可让工具同步长期挂起。
- **判断**：这直接影响 MCP Lazy / MCP Manager 这条 P0/P1 工具发现主线；后续验证不仅看 Schema 成本，还要看 discovery 的 timeout、分页上限与故障隔离。
- **成熟度**：Runtime 风险；等待官方修复，不单独升 Candidate。

### 👀 Session / compaction consumer contract｜⭐⭐⭐⭐½
- 今日另一份 alpha.2 复验指出：插件若写入合法 surface `replace` marker，但 `assistant/message` 的 `turn/step` 为 null，持久化层可接受，token meter 却会拒绝，随后 `/compact` 每次都失败。
- 这暴露的是同一 durable event 在 **Session persistence 与 token-meter consumer 之间 contract 不一致**，对 Memory / recall / compaction 类插件尤其重要。
- **判断**：Session v2 验证需增加“第三方 surface event → token accounting → compaction”跨消费者一致性测试。

### 🧪 dshvm｜Candidate｜⭐⭐⭐⭐
- 今日出现 `dshvm 0.1.0`：以 nvm 类似方式管理多个 DSH 版本，并可为某个版本隔离独立 `$DSH_HOME`，用于把 Session、plugins、settings、credentials 与日常环境分开。
- 这个方向直接对应当前 `0.1.2-rc.1` / `0.1.3-alpha.2` 并行、升级污染和 Session format 不可降级读取的风险。
- **判断**：方向有价值但项目很新，且会自动构建未上 npm 的 prerelease；保持只观察，验证隔离边界、跨平台行为与 rollback 后再决定是否升 P1。

### 趋势判断

今天的核心变化不是“又一个 Alpha”本身，而是 **0.1.3-alpha.2 把风险面从 Session API 继续扩展到了平台分发与跨消费者一致性**：Windows 原生模块安装、MCP discovery hang、token-meter/compaction 对第三方 durable event 的解释差异，都属于 real-host 才会暴露的问题。

因此 0.1.3 后续 gate 应明确分成四层：**安装/平台 → Host/Plugin boot → 模型请求/Tool/MCP → Session migration/compaction/cold recovery**。
