## 2026-09-01～07｜历史基线

9 月 1–7 日完整 Delta 已在此前提交中记录：观察基线从 `0.1.2-alpha.3` → alpha.4 → `0.1.2-rc.1` → `0.1.3-alpha.1`；核心主线包括 Session/Plugin ABI、Subagent continuation、RC 原地升级/混合依赖、Provider settings、Agent Teams × foreground one-shot 互操作、Session v2/SessionHandle/cross-process lock、local-file request extension，以及 Claude Code hooks bridge 的真实 tool-call 兼容故障。

## 2026-09-08｜Delta

### 👀 官方 DeepSeek Harness `0.1.3-alpha.2`｜⭐⭐⭐⭐⭐
- 最新开发基线推进到 `0.1.3-alpha.2`；稳定候选线仍保留 `0.1.2-rc.1`，继续双线观察。
- alpha.2 重点改善 0.1.3 长会话打开、恢复、持续对话时的卡顿与内存占用，并修复 Web 断线后无法自动恢复等问题。
- continuable Subagent 控制面进一步增强：支持消息排队、编辑、删除、Steer 与停止操作；这推进了 Agent Runtime 的“运行中治理”，但 nested waiting/唤醒、one-shot interoperability 与 usage 回传仍未因此自动闭环。
- **判断**：0.1.3 从 alpha.1 的 Session 架构重构进入 alpha.2 的性能/控制面修整阶段，但还不能视为 contract 稳定。
- **成熟度**：Alpha；继续观察。

### 👀 Windows clean install / 原生依赖回归｜⭐⭐⭐⭐⭐
- `0.1.3-alpha.2` 的 JSONL persistence 依赖链新增并精确锁定 `fs-ext@2.1.1`；该包没有预编译二进制，安装脚本直接走 `node-gyp`。
- 已有干净 Windows 11 + Node 24 环境真实报告：没有 Visual Studio C++ Build Tools 时，`npm install -g @deepseek-ai/dsh@alpha` 会在 `fs-ext` 编译阶段失败并整体回滚；同机安装 `0.1.2-rc.1` 成功。
- 社区 Windows Desktop wrapper 已通过固定 Node ABI + 预编译 `fs-ext` 绕开现场编译，侧面说明平台 artifact / native dependency gate 已成为真实分发问题。
- **判断**：Compatibility gate 新增 **OS × Node ABI × native dependency × clean install**；不能只验证 Host boot 和插件 API。

### 🔥 MCP Runtime reliability｜`tools/list` 可被异常分页无限挂起｜⭐⭐⭐⭐½
- 今日公开报告在当前 npm 线（至 alpha.2）复验：MCP `syncTools` 会持续跟随服务端返回的 `nextCursor`，如果异常/恶意 MCP server 永不终止 cursor，Harness 缺少明确 page cap / deadline，可让工具同步长期挂起。
- **判断**：这直接影响 MCP Lazy / MCP Manager 这条 P0/P1 工具发现主线；后续验证不仅看 Schema 成本，还要看 discovery 的 timeout、分页上限与故障隔离。
- **成熟度**：Runtime 风险；等待官方修复，不单独升 Candidate。

### 👀 Session / compaction consumer contract｜⭐⭐⭐⭐½
- 今日另一份 alpha.2 复验指出：插件若写入合法 surface `replace` marker，但 `assistant/message` 的 `turn/step` 为 null，持久化层可接受，token meter 却会拒绝，随后 `/compact` 每次都失败。
- 这暴露的是同一 durable event 在 **Session persistence 与 token-meter consumer 之间 contract 不一致**，对 Memory / recall / compaction 类插件尤其重要。
- **判断**：Session v2 验证需增加“第三方 surface event → token accounting → compaction”跨消费者一致性测试。

### 🧪 dshvm｜Candidate｜⭐⭐⭐⭐
- 今日出现 `dshvm 0.1.0`：以 nvm 类似方式管理多个 DSH 版本，并可为某个版本隔离独立 `$DSH_HOME`，用于把 Session、plugins、settings、credentials 与日常环境分开。
- 这个方向直接对应当前 `0.1.2-rc.1` / `0.1.3-alpha.2` 并行、升级污染和 Session format 不可降级读取的风险。
- **判断**：方向有价值但项目很新，且会自动构建未上 npm 的 prerelease；保持只观察，验证隔离边界、跨平台行为与 rollback 后再决定是否升 P1。

### 趋势判断

今天的核心变化不是“又一个 Alpha”本身，而是 **0.1.3-alpha.2 把风险面从 Session API 继续扩展到了平台分发与跨消费者一致性**：Windows 原生模块安装、MCP discovery hang、token-meter/compaction 对第三方 durable event 的解释差异，都属于 real-host 才会暴露的问题。

因此 0.1.3 后续 gate 应明确分成四层：**安装/平台 → Host/Plugin boot → 模型请求/Tool/MCP → Session migration/compaction/cold recovery**。

## 2026-09-09｜Delta

### 👀 官方 DeepSeek Harness `0.1.5-alpha.1`｜⭐⭐⭐⭐⭐
- 官方在 2026-09-08 发布 `0.1.5-alpha.1`，最新开发基线从 `0.1.3-alpha.2` 直接推进到 0.1.5；稳定候选线仍单独保留 `0.1.2-rc.1`。
- **Session format 升至 V3**：恢复受支持的旧 Session 时会生成新版日志并保留原文件；system prompt 正式进入 message history；旧 PTC event 和 `code` preset 引用自动迁移；自定义 log reader 必须适配 V3，而且升级后的 Session 不支持降级读取。
- **Agent / Inbox API 再次 breaking**：移除 `ctx.agent`，调用方必须显式传 Agent；`Inbox` 变成 type-only interface，插件经 `agent.inbox` 访问待处理消息，`hasPending` / `claim` 不再是 public API。
- **判断**：0.1.5 不是 alpha.2 的小修，而是新的 durable log + Agent Runtime contract generation；所有深耦合 Session / Agent / Memory / orchestration 插件都应重新做 real-host gate。
- **成熟度**：Alpha；继续观察。

### 🔥 Dynamic system prompt × KV Cache｜⭐⭐⭐⭐⭐
- 0.1.5-alpha.1 新增一条直接影响 Harness 推理机制的官方能力：当配置模型**显式声明支持**时，可以动态修改 system prompt 而不使 KV Cache 失效。
- 这与 Radar 长期关注的 Anchoring / persona routing / near-distance Context injection 高度相关：过去“动态改 prompt”和“保持稳定前缀/cache”往往是冲突变量，现在官方开始给出能力协商面。
- **判断**：提升为 P0 观察点，但目前不能外推为“动态 prompt 一定提升能力”；重点要看支持模型、cache hit、真实 coding trajectory A/B、identity/constraint drift。
- **成熟度**：官方 Alpha 能力；继续观察。

### 🔥 dsh-context `0.46.1`｜V0/V2/V3 兼容实证｜⭐⭐⭐⭐⭐
- `dsh-context` 今日已经公开 `0.1.2-rc.1` V0、`0.1.3-alpha.2` V2、`0.1.5-alpha.1` V3 的三代兼容矩阵，并对 alpha.2 / alpha.5 做了 disposable-profile install → composed row → uninstall 的实际验证。
- 它没有按 Harness version 分支，而是按日志 shape 折叠：V3 的 system prompt 改为 `system/message` surface node，replacement endpoint 改为 `{startSeq,endSeq}`，PTC dispatch 改为 `tool/ptc-dispatch`。
- **判断**：这是今天最有价值的第三方兼容证据之一，因为它把“支持最新版”具体化成 durable-log generation contract；`dsh-context` 保持 P0 / 可日常尝鲜。

### 👀 Subagent ownership / scheduling｜⭐⭐⭐⭐½
- 0.1.5-alpha.1 修正 continuable Subagent 的归属，避免它们被当作 root Session 参与只应针对根会话的定时调度；同时可选 Subagent runtime 更新到 Codex 0.153.4 和 Claude Code 2.1.263。
- **判断**：这是 Agent Teams / Conductor 长期主线里的实质 Runtime 修正，但 waiting→自动唤醒、foreground/background/continuable 共存、usage 回传仍没有因此闭环。
- **成熟度**：官方实验性；继续重点观察。

### 👀 官方 Sidebar 与社区工作台能力开始重叠｜⭐⭐⭐⭐
- 0.1.5-alpha.1 新增实验性右 Sidebar，支持多标签、分栏、全屏，并可直接打开聊天文件链接和产出文件；原 Detail panel 被移除。
- **判断**：这第一次明显碰到 better-sidebar / dsh-web-ui 等社区工作台的核心产品层价值。暂不判定“官方取代”，但后续要把社区项目是否仍提供第三方页面、终端 park、多 Workspace、Remote/Doctor 等官方未覆盖能力作为留在 P1 的依据。

### 趋势判断

今天的阶段变化很明确：DSH 最新开发线已经从 **Session V2 / SessionHandle 的实验阶段，推进到 Session V3 + Agent/Inbox API 显式化**。这意味着 0.1.5 的兼容验证不能只做 boot 或 install，必须把 **旧 Session migration、自定义 log reader、Agent ownership、Inbox、模型请求/Tool 路径**一起纳入。

另一条更重要的 P0 信号是：官方首次把 **动态 system prompt 与 KV Cache 保持**做成显式模型能力。它有机会把 Anchoring / routing / persona-context 这类社区实验从“绕 Harness 行为”推进到“利用官方 capability negotiation”，但真正价值仍需真实任务 A/B，而不是只看接口存在。

## 2026-09-10｜Delta

### 👀 官方 DeepSeek Harness `0.1.5-rc.1`｜⭐⭐⭐⭐⭐
- 官方于 2026-09-10 发布 `0.1.5-rc.1`，0.1.5 正式进入首个 RC；Radar 主兼容基线由 `0.1.2-rc.1` 推进到 **`0.1.5-rc.1`**。9 月 9 日发布的 `0.1.5-alpha.2` 作为中间版本已被 RC1 覆盖。
- RC1 将最近两条 Alpha 的关键能力合并进候选版：Session V3 / `SessionHandle` / session lock、动态 system prompt 且保持 KV Cache、continuable Subagent 队列/编辑/删除/Steer/停止、Agent Teams 可安装包、Sidebar 文档/文件交付、任意类型文件上传、自定义 Provider models discovery，以及全局 HTTP(S) proxy。
- 新会话默认模型改为 **DeepSeek-V41-Flash (`deepseek-flash`)**，支持文本、图片与会话历史中的 system prompt 更新；显式模型配置仍优先。
- **判断**：后续不再把 `0.1.2-rc.1` 当“稳定候选主线”，它只保留为升级/回归对照。真正需要验证的是 `0.1.2-rc.1 → 0.1.5-rc.1` 的原地升级、旧 Session、深耦合插件与多 Agent 冷恢复。
- **成熟度**：RC；继续观察。

### 🔥 Runtime closure｜MCP / Provider / tool-call 三个长期问题进入 RC 修复｜⭐⭐⭐⭐⭐
- RC1 release notes 明确收录三个此前 Radar 已追踪的问题修复：
  1. DeepSeek 流式工具调用的续传分片不再用空 `id/name` 覆盖已有 tool-call identity，避免 `unknown tool ""` 及不可重开 Session；
  2. 无效/过期 pi-ai 配置不再让整个模型设置入口消失，并保留诊断修复入口；
  3. MCP 工具发现拒绝**重复分页 cursor**，避免启动/同步无限等待，并保留上一组可用工具。
- **判断**：这三项都属于“真实 Runtime contract closure”，不是 UI 小修；其中 MCP Lazy 后续可把重复 cursor hang 从未解决风险降为“RC1 已有官方防护，继续验证 deadline/page-cap 与恶意非重复无限分页”。

### 🔥 Session V3 historical migration｜旧 Subagent descriptor v2 仍是高风险验证点｜⭐⭐⭐⭐⭐
- 9 月 9 日新报告指出，V0→V1 migration 对 `subagent/descriptor` 直接要求 `version=3`；而 2026-08-24 之前多个正式/RC 版本写出的 descriptor 是 version 2。
- 报告给出一个真实 321-log store：291 条含 `subagent/descriptor`，其中 **282 条是 version 2**，当前迁移会拒绝这些日志；失败是 fail-closed、原文件保留，但会话会“列表可见、点击无法打开”。报告还指出这些 v2 payload 按 v3 disposition 本身并没有字段违规，拒绝发生在 payload 结构校验之前。
- **为什么重要**：RC1 已把 V3 migration 作为正式候选路径，但“支持旧日志迁移”不能仅靠 release note 判断，必须拿真实历史 corpus 验证，尤其是早期用过 Subagent 的用户。
- **成熟度**：RC migration 风险；默认继续观察，不做本地迁移尝试。

### 👀 Web fetch / Proxy SSRF boundary｜⭐⭐⭐⭐½
- 9 月 9 日出现 0.1.5-alpha.1 的 SSRF 报告：启用 HTTP(S) proxy 后，`web_fetch` 的 proxied branch 跳过 hostname 的 `resolvePublicAddresses` / IP pinning，只对 URL 中直接写出的非公网 IP literal 做拒绝；若 hostname 由代理 DNS 解析到内网/metadata 地址，存在绕过 public-address enforcement 的风险面。
- 今日直接复核 **`dsh-v0.1.5-rc.1` tag** 的 `packages/web/web-fetch-http/src/provider.ts`，这一分支逻辑仍存在：`route.proxied && !isNonPublicIpLiteral(url.hostname)` 时直接走 `requestVia(...)`，未先做 hostname public-address resolution。
- **为什么重要**：0.1.5 RC 同时把“所有出站请求遵循 HTTP(S)/ALL_PROXY/NO_PROXY”作为正式能力；企业代理/内网环境下，这会把 web 工具的 SSRF 威胁模型放大到实际 Agent Runtime 安全边界。
- **成熟度**：待官方处置的 RC 安全风险；继续观察，不安装任何第三方修复插件。

### 🧪 dsh-plugin-upgrade｜Candidate｜⭐⭐⭐⭐
- 官方 0.1.1→0.1.2 upgrade-skill 讨论中出现新的专门实现 `dsh-plugin-upgrade`：锁定 `0.1.3-alpha.1 → 0.1.5-alpha.1` 迁移走廊，提供按需加载的 upgrade skill 与零依赖、只读、无网络/无子进程的 seam scanner；作者报告使用 40 个真实插件仓作为适配语料。
- **判断**：方向与当前 RC 迁移需求高度吻合，但它的事实卡终点仍是 alpha.1，今天 RC1 已发布，因此先放 Candidate；只有补齐 `0.1.5-rc.1` exact-tag / published-tarball / real-host gate 后才考虑升 P1。

### 趋势判断

今天是 0.1.5 的阶段分界点：**关注重点从“Alpha 期间 API 怎么变”切换为“RC1 能不能把历史数据、插件组合、Provider/MCP、Agent Runtime 与安全边界真正收住”。** 官方已经开始关闭几个长期 Runtime 问题，但 Session V3 的真实历史迁移仍暴露出高价值反例。

下一阶段最值得盯的四条线是：**旧 Session/Subagent corpus migration、Agent waiting/Steer/cold recovery、RC1 插件 real-host compatibility、Proxy/Web fetch 安全边界**。

## 2026-09-11｜Delta

### 👀 官方 DeepSeek Harness `0.1.5-rc.2`｜⭐⭐⭐
- 官方已发布 `0.1.5-rc.2`，因此“当前最新 RC”从 rc.1 推进到 **rc.2**；但 release notes 只有反馈提交体验、交付文件卡片/对话间距与代码文件图标等 UI 优化。
- **判断**：版本基线应更新到 rc.2，但它本身**不满足重大能力/Runtime 成熟度提升**的标准；今天真正重要的是 rc.1/rc.2 代际暴露出的迁移与插件 ABI 问题。
- **成熟度**：RC；继续观察。

### 🔥 Profile / Preset migration｜官方 persona `text → prefix` 可直接阻断新会话｜⭐⭐⭐⭐⭐
- 0.1.5 RC 的官方 `@deepseek-ai/dsh-persona` 把配置字段从 `text` 改为 `prefix`，但公开报告显示用户保存在 `~/.dsh/.agent-presets/` 的旧自定义 preset 没有自动迁移，也没有在升级时预检。
- 如果默认 agent preset 仍引用旧 persona 配置，session resume 阶段会因 `$.prefix missing required value` 失败，表现为“新会话按钮无反应”；重装 DSH 也不会清掉这些持久 preset，因此问题会跨升级持续存在。
- **判断**：Compatibility gate 需要新增 **持久 Profile/Preset schema migration + upgrade-time validation + UI surfaced error**，不能只测 package/API/Session 日志。
- **成熟度**：RC 升级风险；默认继续观察。

### 🔥 Plugin Web/RPC extension seam｜`connection.rpc.handle()` 在 0.1.5 RC 可让整类插件前端失联｜⭐⭐⭐⭐⭐
- 多个第三方插件已复现：调用公开 `connection.rpc.handle(channel, handler)` 时同步抛出 `cannot get property 'webServer' without inject`，导致 RPC channel 根本没有注册，浏览器 POST 最终落到 SPA/static fallback 并返回 405。
- 已观察到 `dsh-mnemon`、`dsh-vision-router` 等插件的 Web 设置/状态面板受影响，而 agent-side tools 仍可运行，说明这是 **Host↔Client extension seam** 的系统性断裂，而不是单个插件业务 bug。
- RC2 官方说明仅包含 UI 体验调整，未声明修复此类插件 RPC contract；因此 rc.2 仍需要 exact-tag real-host 复验。
- **判断**：把第三方插件兼容 gate 明确增加 **Host RPC registration + authenticated POST round-trip + Web panel functional test**。
- **成熟度**：RC Plugin ABI 回归；重点继续观察。

### 🔥 Session V3 migration｜新增 `unclassified message source` 历史会话拒绝样本｜⭐⭐⭐⭐½
- 继旧 `subagent/descriptor version=2` 后，又出现 rc.1 历史会话加载失败：迁移器报 `cannot safely transform unclassified message source`，原始 V0 artifact 保持不变。
- 这说明 V3 migration 的风险并不限于单一 Subagent descriptor 版本，而是**历史 message source 分类覆盖率**本身还不完整；对长期使用旧 Harness、第三方插件或 gateway/internal 来源事件的 Session 尤其需要真实 corpus 验证。
- **判断**：Session V3 gate 从“指定旧事件 shape”升级为 **多来源历史日志 corpus + fail-closed 分类覆盖 + cold reopen/compaction**。
- **成熟度**：RC migration 风险；继续观察。

### 👀 第三方 Runtime streaming contract｜0.1.5 可出现“安装/探针都成功，但 Assistant 文本为空”｜⭐⭐⭐⭐½
- OpenDesign 的 DSH runtime 在 0.1.5-rc.1 上可正常安装、通过 probe、列出模型，但真实会话不再收到旧 `assistant/chunk` 流式文本，最终连接测试以“exit 0 但无输出”失败；切回 0.1.2-rc.1 后恢复。
- 这提供了一个很好的兼容反例：**peer range、安装、Host boot、probe、models API 全通过仍不足以证明运行兼容**；必须跑一轮真实 assistant text/thinking/tool 事件链。
- **判断**：Compatibility gate 增加 **end-to-end assistant stream/result assertion**，并优先验证 projection/text-chunks 等新通道是否成为 0.1.5 正式扩展面。

### 趋势判断

今天没有新的 P0 推理机制突破，`0.1.5-rc.2` 本身也只是小型 UI RC；真正的增量集中在 **“升级后的持久状态”和“第三方扩展 seam”**。0.1.5 已经证明，Session log、Preset schema、Host RPC、Assistant streaming 四层都可能出现“表面版本兼容、真实运行不兼容”。

因此 RC gate 继续收紧为：**安装/平台 → Profile/Preset migration → Host/Client RPC → assistant stream/tool → Session corpus migration/cold recovery**。
