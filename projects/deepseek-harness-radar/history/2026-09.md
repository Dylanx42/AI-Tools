# DeepSeek Harness Radar｜2026-09 历史

> 当前状态 Dashboard：`../RADAR.md`。本文件只记录 2026-09 的每日增量。

## 2026-09-01｜Delta

### 👀 官方 DeepSeek Harness `0.1.2-alpha.3`｜P1
- 官方于 2026-08-31 16:03 UTC 发布 `dsh-v0.1.2-alpha.3`，9 月 1 日观察窗口已进入 alpha.3 cohort。
- 长会话右侧导航可预览/跳转尚未载入的分页轮次，并继续降低长会话渲染内存和代码高亮开销。
- 修复运行中追加/排队图片的回显与可靠投递，持续 Subagent 的 follow-up 也支持图片；`read_image` 可按内容识别无扩展名图片附件。
- **破坏性/迁移点**：移除可选 SQLite Session persistence backend；官方明确要求已有 SQLite 内容在旧版本中先导出。
- **判断**：0.1.2 的兼容窗口继续快速移动，alpha.2 的兼容结论不能自动外推到 alpha.3。

### 👀 Compatibility / Upgrade｜alpha.3 新迁移面
- 社区已出现基于 alpha.3 的真实迁移证据：旧 profile 可能因 core bundles 不再隐式注入而出现插件等待 `webServer` / `llm` 等核心服务的启动失败，需要重新核验 profile bundle contract。
- 已有第三方插件开始显式声明 `@deepseek-ai/dsh >= 0.1.2-alpha.3`，并迁移到 generated `ctx.remote` Client API、移除已退休 `dsh-client-runtime` 依赖。
- **判断**：Upgrade Skill / compatibility matrix 需要从 alpha.2 事实卡继续推进到 alpha.3，尤其覆盖 profile/core bundle、Client API 与 Session persistence。

### ⚠️ Runtime reliability｜alpha.3
- 新报告显示 `0.1.2-alpha.3` 存在“任务回答后仍持续生成、不停止”的现象，而且报告者称切换多个 Provider 后仍可复现；目前仍是单个社区 bug report，尚未确认根因。
- **判断**：先作为 Runtime 风险跟踪，不单独升 Candidate；等待更多复现或官方确认。

### 趋势判断

9 月第一天的核心变量不是新插件数量，而是 **官方 alpha.3 再次改变兼容基线**。接下来优先验证 P0/P1 项目是否明确通过 alpha.3，而不是继续沿用 alpha.2 的“兼容”标签。

尤其值得盯住三类迁移面：**profile/core bundle 组合、Client API/Remote contract、Session persistence**。这也进一步强化 Compatibility / Upgrade Skills 作为生态基础设施主线的价值。
