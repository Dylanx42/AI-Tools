## 2026-09-24｜Delta

### 🔥 官方 `0.1.7-rc.1`：进入候选线，但迁移与发行 correctness 仍未闭环｜⭐⭐⭐⭐⭐
- 官方于 2026-09-23 发布 `dsh-v0.1.7-rc.1`。Release 明确收口多条此前 Radar 主线：可选插件失败不再拖垮其余插件；旧 Subagent 完成通知在 Messages 下导致父会话不可继续的问题已修；重复申请当前权限不再审批；源码启动 module-runtime 初始化失败已修；主动 compaction 开始预留模型输出预算；Headless 新增 stdin、`--session-id` continuation 与 JSONL event 输出；MCP 升至 SDK v2 并支持资源/URI template。
- 这说明 0.1.6/0.1.7 Alpha 阶段暴露的 **optional capability fault isolation、Messages durable-history compatibility、sandbox same-mode normalization、source-launch module identity、compaction output reserve** 已有官方吸收/修复，成熟度相对 alpha 明显提高；但不能据此视为可日常基线，因为 release 后仍有新回归。

### 🔥 `0.1.7-rc.1` HTTP proxy × Node fetch dispatcher incompatibility｜⭐⭐⭐⭐½
- 9 月 24 日新增最小复现：自定义 OpenAI-compatible Provider 经 HTTP proxy 做模型发现时稳定报 `did not answer with JSON`；同 URL 的 curl / 独立 Node fetch 正常。报告将根因定位到 `dsh-http-proxy` 把 undici@8 dispatcher 注入 Node 内置 fetch 后，HTTPS response headers 丢失；Node 26 路径可恢复。
- **影响**：这是 Provider discovery / 企业代理场景的真实 RC 回归，不是 UI 噪声；需要按 Node 版本 × proxy × HTTPS gateway 做 matrix，不能只验证 direct-connect。

### 👀 Config-schema diagnostics 与升级可恢复性｜⭐⭐⭐⭐
- 同日 `--dump-config-schema` 在 pristine factory Web profile 上可因 `dsh-agent-preset` EntryGroup carrier 报 `unrecognized Loader tree carrier` 并 exit=1，说明 Doctor/diagnostics 自身仍可能在出厂配置上失败。
- 社区升级恢复清单汇总 0.1.5→0.1.7 的多条已验证迁移故障，并特别指出 `0.1.5-rc.3` 曾存在 npm tag / sibling package publication 不一致。发行工程因此继续属于 Compatibility 一级 gate：Release/tag、npm 可安装性、内部 sibling 完整性必须一起核验。

### 趋势判断

`0.1.7-rc.1` 是今天真正的阶段转折：官方已经吸收并修复了一批 Radar 连续跟踪的 Alpha correctness 问题，说明观察方向有效；但 RC 当天仍出现 proxy/provider discovery 与 config-schema diagnostics 回归，所以当前建议是 **把主观察线推进到 0.1.7-rc.1，但仍不把它升级为“可日常使用”的稳定基线**。

下一轮优先验证：**legacy V2/V3→V4 repair 是否真正闭环、旧 custom preset 是否有官方迁移路径、RC1 proxy/Node matrix、compaction progress invariant（不仅是 output reserve）、以及 Headless JSONL continuation 的 effective-config correctness。**
