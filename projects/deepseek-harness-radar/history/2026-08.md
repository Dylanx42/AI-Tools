### 👀 dsh-market 1.31.0 → 1.31.1｜P1

- **判断**：Market 已明显进入“包管理器/生命周期诊断”阶段，而不只是插件商店。
- **成熟度**：可日常使用；继续观察。

### 👀 dsh-plugin-hub / dsh-mcp-manager｜P1 候选
- `dsh-mcp-manager` 支持按工作目录维护项目级/全局 MCP，并可把项目级 MCP 收敛成 `ws_mcp_search` / `ws_mcp_call` 两个原子工具，方向与 `dsh-mcp-lazy` 一致，都是在控制 Tool Schema / Context 成本，只是实现路径不同。

- **判断**：先列 P1 候选，后续重点比较它和 `dsh-mcp-lazy` 的 Tool Schema 收敛方式、兼容性与安全边界。
- **成熟度**：可尝鲜；只观察。

### 👀 dsh-TUI 0.9.3｜P1
- 新增 Linux / Windows / macOS 的跨平台单文件便携包、Release 自动构建、自更新、原子替换与 Session 保留重启；Linux arm64 也已加入 target。
- 随后修复 pnpm 11 原生依赖 build-script approval 导致 0.9.3 portable bundle 被阻断的问题。
- **判断**：今天提升的是“分发和自更新成熟度”，不是 Harness 能力本身，所以维持 P1，不上调。

### 趋势判断

## 2026-08-27｜Delta

今天有 5 项值得留档的实质变化；官方 `deepseek-ai/deepseek-harness` 主仓仍没有新提交，最新正式提交仍是 2026-08-21 的 `0.1.1-rc.2`。

### 🔥 dsh-agent-teams 0.1.14｜P0
- 完成 **staged plan review** 工作流：普通 `/agent-teams` 先只落盘 roster + DAG，不创建子会话、不领取任务；成员模型/推理等级直接读取 Harness 模型目录。
- 用户现在可以在执行前选择「继续规划」回到聊天让 Captain 重做方案、放弃计划，或 **Approve & Run** 后再原子创建成员并启动 ready tasks；运行中的团队停止也移动到具体团队面板，并增加二次确认。
- **为什么重要**：这把多 Agent 从“命令一发就开始跑”推进到真正的 **plan → human review → execution**，明显改善误启动、错误路由和昂贵团队任务的可控性。
- **成熟度**：可尝鲜；继续观察。重点对比官方 experimental Agent Teams 是否也会走 staged approval。

### 🔥 dsh-context 0.34.0｜P0
- 新增 **Agent Network**：把当前 Agent、祖先和任意深度 Subagent 画成实时节点图，每个 Session 显示 context ring、lineage、运行状态，并可点击跳转到对应 Session。
- 这使它从“单 Session Context Inspector”扩展成 **多 Agent Context/拓扑可观察层**；对 Agent Teams、Subagent 与 Context budget 调试都更有价值。
- **成熟度**：可日常尝鲜；继续重点观察。

### 👀 dsh-market 1.33.0｜P1
- 新增 **Public Update API（beta）**：第三方插件自己的设置页可以通过 Market 的 versioned capabilities API 发起安全更新，不必自己重写 pnpm、失败处理、rollback、restart 判断。
- 每个 mutation 有 same-origin guard，rollback 复用 Market 现有受控逻辑；API 明确标记 `stability: beta` 并有 contract test。
- 同时继续修 Desktop 下“stale profile-local official bundle”导致健康更新被错误回滚的问题。
- **为什么重要**：Market 开始从“独立插件商店”变成 **插件生命周期服务层**，其他插件可以安全复用更新基础设施。
- **成熟度**：可日常使用，Public API 为 beta；继续观察。

### 👀 dsh-TUI｜P1
- `/compact` 与 `/model`、`/resume`、`/rewind`、`/fork`、`/new` 等 agent 替换入口现在串行化，切换前会取消并等待在途 compaction，避免旧会话后台提交 checkpoint 导致新会话只剩摘要/上下文丢失。
- 便携包更新链补齐 SHA256 校验、流式大小上限、zip-slip/symlink/hardlink 树校验、缓存哈希守卫、frozen lockfile，并收口 OSC 8 / URL scheme 等终端注入面。
- **为什么重要**：这是 Session 生命周期与供应链安全的实质成熟度提升，而不是终端外观功能。
- **成熟度**：可日常尝鲜；继续观察。

### 🧪 dsh-auto-maintenance 1.2.1｜Candidate
- 新出现的插件生命周期自愈方向：插件安装/卸载后自动创建状态快照并执行 `dsh --profile web --dump-config` 等检查，失败时回滚到最近一次成功快照；连续启动失败时外部 rescue 脚本尝试诊断、重启，仍异常才回滚。
- v1.2.1 修了 rescue/watch 脚本在 `type: module` 包中直接运行会 `require is not defined` 的问题，并把原先较激进的回滚流程改成 **restart + health check first → rollback only if still unhealthy**。
- **判断**：方向和 Market/Doctor/Compatibility 很吻合，但项目很新、自动回滚权限很重，暂只放 Candidate，不建议安装。

### 趋势判断

今天最明显的是两件事：**多 Agent 开始补“执行前治理”**，而插件生态开始补“运行后治理”。前者是 staged plan review / Agent Network，后者是 Market Public Update API、TUI 生命周期保护和 auto-maintenance 自愈。

## 2026-08-28｜Delta

今天有 4 项值得留档的实质变化，**其中官方 `0.1.2-alpha.1` 是这几天最重要的变化**。

### 👀 官方 DeepSeek Harness `0.1.2-alpha.1`
- 官方在 2026-08-27 发布 `dsh@0.1.2-alpha.1`，主线重新进入高频底层重构，不再只是 0.1.1 的 Vision / Attachment 扩展。
- `code-mode` 已重命名为 **PTC mode**；同时 Session 持久化读路径改成 **known-event fail-closed**：未知持久事件类型会拒绝读取，旧的 `ignorable` 机制被移除。
- 这对插件生态影响很大：任何写入自定义 durable session event 的第三方插件，都需要新的正式注册/迁移 surface，否则新版可能出现历史会话不可读。社区今天已经围绕这点集中提出兼容请求。
- **判断**：Radar 的第一观察重点改为 `0.1.2 alpha × plugin/session compatibility`。
- **成熟度**：Alpha；继续观察，不建议把现有稳定插件环境直接迁过去。

### 👀 dsh-market `1.35.0`
- 修复了一个真正会“把整个 Profile 弄到启动不了”的生命周期问题：安装后验证触发插件卸载时，如果 pnpm 已删包但返回异常，旧逻辑可能留下孤儿 `dsh.profile.bundles` 行，下一次 Loader 直接在启动阶段失败，连 Market 页面都进不去。
- 1.35.0 现在按磁盘真实状态做 reconcile，并新增**跨重启持久化、脱敏、限额的 NDJSON 诊断日志**；更新动作还会核验最终实际落盘版本，避免 pnpm release-age 策略把旧版本解析成“成功更新”。
- 后续又补了 mirrored GitHub install 的完整性保护。
- **判断**：继续 P1，但“恢复/诊断基础设施”权重再上调；接下来重点看 0.1.2 alpha 兼容。
- **成熟度**：可日常使用；继续观察。

### 🔥 Anchored Standard｜identity drift 已正式记录为已知行为
- bare Minimal persona (`You are a helpful software engineer assistant.`) 在 `deepseek-v4-pro` 上遇到身份问题时可能回落到训练先验，实测会自称 Claude。
- 一行 identity anchor（`You are an AI agent powered by DeepSeek Harness.`）可修复该行为，同时首轮 2-tool schema、context suppression、promotion 等**机械 anchor 检查保持正常**。
- 但维护者没有给出真实 coding task 的 trajectory-style A/B，因此还不能说“加 identity line 完全不影响 Anchoring 的模型轨迹”。
- **判断**：不是 Anchoring 机制失效，但暴露出“极简 prompt ≠ 无行为副作用”的边界；P0 不变，增加 identity/persona drift 观察项。
- **成熟度**：实验性；继续观察。

### 🧪 `dsh-durable-context`｜新 Candidate
- 新的长会话 Context 方案：明确把 **“durable state 已保存”** 和 **“旧 conversation context 已被证明可安全回收”** 分成两个独立状态转换。
- 已保留 2026-08-28 的机器可读 qualification：先形成结构化 investigative state，随后 `/compress` 做 coverage audit，把此前仍只存在旧上下文里的关键事实显式 transfer，再在 host injection / fresh chat 中恢复。
- 这个方向比普通 Memory 插件更接近 Context/Compaction 核心问题，但项目很新，而且 README 自己已经记录了 non-Git workspace 下项目隔离可能不可靠。
- **判断**：先放 Candidate；重点看它和官方 compaction/session persistence、0.1.2 alpha 的边界。
- **成熟度**：实验性；只观察。

### 趋势判断

今天最大的变化不是社区又出现了什么插件，而是**官方 0.1.2 alpha 把 Session persistence / plugin ABI 兼容问题重新推到最前面**。接下来几天所有 P0/P1 项目都需要重新验证 `0.1.2-alpha.1`，特别是会写 Session durable event、做 Context/Compaction、Agent Teams、Remote/TUI 的插件。

另一条线也更清楚了：极简 Harness / Minimal persona 在降低 Tool/Context 干扰的同时，会暴露 identity drift 这类行为边界，所以后续不只看 benchmark，还要看 persona/identity/constraint 是否在“减法”过程中被误删。

## 2026-08-30｜Delta

今天有 4 项值得留档的实质变化；`RADAR.md` 已同步更新。

### 👀 官方 DeepSeek Harness `0.1.2-alpha.1`｜P1
- 进一步核实发布状态：`dsh-v0.1.2-alpha.1` 当前是 **GitHub tag/source release**，但官方 npm 发布工作流没有执行；截至今天 npm `latest/next` 仍停在 `0.1.1-rc.2`。

- **为什么重要**：这意味着“官方出了 alpha”不能等同于“普通用户已有正式 npm 安装路径”，对插件兼容判断必须区分源码 alpha 与 npm RC。
- **成熟度**：Alpha；继续观察。

### 🔥 dsh-context `0.38.3`｜P0
- 当前版本已到 `0.38.3`。更关键的是它已经把 DSH session-projection 的两代 contract 本地镜像成兼容层，同一份定义可覆盖 `0.1.0-rc.7` 到 `0.1.2-alpha.1`。
- 同时修复 alpha 下一个真实破坏：projection view 中显式 `undefined` 会被 Harness 的 lossless-JSON 管线整体拒绝，导致新建空 Session 的 projection push / Session list 异常；现在未知字段改为“键不存在”，并增加 plain-JSON 回归测试。
- **为什么重要**：Radar 里原先的“0.1.2 alpha 兼容待验证”可以改成“关键 projection 路径已有直接兼容证据”，而且这个问题正好验证了 alpha 的严格 JSON contract 会真实影响第三方插件。
- **成熟度**：可日常尝鲜；继续重点观察 alpha 后续 contract 漂移。

### 👀 dsh-market `1.38.0`｜P1
- 修复一个比之前更危险的失败更新场景：`pnpm add` 可能已经替换 `package.json` 和已安装包目录，却最后返回非零；旧失败路径只恢复 manifest，导致 UI 显示“更新失败”，但重启后实际跑的仍是被拒绝的新版本。
- 现在失败恢复会精确 pin 回之前的版本或 commit，随后回读磁盘并验证入口可加载；如果恢复本身失败，会明确报告而不是假装已回滚。
- 同一版本还恢复了针对 DSH alpha 的真实宿主 Web E2E，适配新的认证与 Settings Remote transport，并明确禁止该 lane 采集 trace/HAR 以避免 session cookie 泄露。
- **为什么重要**：Market 的 rollback 从“恢复配置声明”升级成“恢复并验证实际运行字节”，生命周期可靠性再上一个台阶。
- **成熟度**：可日常使用；继续观察。

### 👀 dsh-TUI｜P1
- 补录 8 月 29 日尚未进入时间线的一项实质变化：TUI 开始公开第三方插件接缝，新增 `./api`、`./test-utils`、`ctx.tuiToast`，并给接缝做稳定性分级；同时接入动态 permission preset registry 和 runtime theme plugin。
- **为什么重要**：它不再只是“一个替代 Web 的终端客户端”，而是在往 **可承载 DSH 第三方插件的前端 Runtime** 演进；这会直接影响未来 TUI 插件生态是否能独立形成。
- **成熟度**：可日常尝鲜；公开 API 中仍有实验性部分，继续观察。

### 趋势判断

今天没有新的 Anchored Standard 或 Agent Teams 核心机制突破，真正变化集中在 **alpha 兼容与插件生命周期工程化**：`dsh-context` 已开始用跨版本 contract 适配对冲上游快速变化，`dsh-market` 则把失败更新恢复推进到“真实字节级验证”。

另一个值得继续盯的方向是官方讨论中的 **external durable Session event / per-Subagent cwd extension contract**。已有社区 fork 给出实现和测试，但尚未被官方上游采纳，所以今天不升 Candidate，只作为 `0.1.2 alpha × plugin ABI` 主线的一部分继续观察。
