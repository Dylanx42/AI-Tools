## 2026-08-31｜Delta

今天有 4 项真正改变 Radar 判断的增量；`RADAR.md` 已同步更新。

### 👀 官方 DeepSeek Harness `0.1.2-alpha.2`｜P1
- **核心变化**：`0.1.2-alpha.2` 已于 2026-08-30 真正发布到 npm 的 `alpha` dist-tag。昨天“0.1.2 只有 GitHub source preview、无法常规 npm 解析”的判断到 alpha.2 已失效。
- 社区已经开始直接 diff `0.1.1-rc.2` 与 `0.1.2-alpha.2` 发布 tarball，并用真实插件做 typecheck/build/boot 验证，不再需要 alpha.1 的 source-built tarball/overrides workaround。
- **为什么重要**：0.1.2 的插件兼容从“源码预研”进入“正式发布 cohort 上的可重复迁移测试”阶段。
- **成熟度**：Alpha；继续观察，不建议当生产稳定版。

### 👀 Compatibility / Upgrade Skills｜P1
- 官方在 8 月 30 日明确公开征集一个 **面向插件作者的 0.1.1→0.1.2 升级 skill**。
- 社区已经提交多种实现：基于版本 hop 的事实卡、npm tarball `.d.ts` diff、contract surface 扫描、依赖 bump、真实 Host/Client boot 验证，以及无人值守迁移 bot 思路。
- **为什么重要**：插件兼容已从“社区各自踩坑”升级为官方准备产品化的开发者基础设施问题。
- **成熟度**：方案成型期；继续观察官方最终采用哪种结构。

### 🔥 dsh-agent-teams 0.1.14｜P0 兼容性下调
- 在 DSH Desktop 2.0.4（bundled 0.1.2-alpha.1）上确认 renderer boot failure：插件仍注入已被移除的 `conversationEvents`，而上游已迁移到 `uiConversation`。
- 移除该插件后 Desktop 可恢复启动；迁移到 `uiConversation` 的修复 PR 已存在但尚未进入已发布版本。
- **为什么重要**：这是我们一直担心的“0.1.2 alpha 前端 ABI 变化会让成熟插件直接阻断宿主启动”的真实案例。
- **成熟度**：插件本身可尝鲜，但必须严格版本匹配；继续观察后续正式修复版本。

### 🧪 dsh-subagent-contract｜新 Candidate
- 新出现一个独立 post-run verifier：直接重读父/子 Session 的持久化日志，不看“最终回答像不像成功”，而验证 parent/depth/admission/follow-up/report 等 durable relation 是否真的成立。
- 已使用 `@deepseek-ai/dsh-sdk-client@0.1.2-alpha.2` 跑通四类真实场景，并保存结构化、fail-closed 的复核证据。
- **为什么重要**：它正好补了 Agent Teams/Subagent 生态缺少“跨 Session durable correctness”验证的问题。
- **成熟度**：Research preview；只观察。

### 趋势判断

今天最关键的转折是 **alpha.2 进入 npm**：从现在开始，0.1.2 兼容可以基于同一套正式发布包做可重复测试，插件 migration skill、compatibility matrix、真实 boot gate 的价值会快速上升。

同时 `dsh-agent-teams` 的真实崩溃案例说明，0.1.2 的 breaking changes 不是抽象 API diff，而是可能让单个第三方插件把整个客户端启动拖死。后续“兼容预检 + 故障隔离 + 自动迁移”会成为 P1 基础设施里的核心主线。

## 2026-08｜月度总结

1. **DSH 生态从“插件数量增长”转向“平台分层”**：Harness 推理、Agent Runtime、Provider、插件基础设施、Web/TUI/Remote 五层逐渐清晰。
2. **动态 Tool Schema 成为最重要的模型表现研究线**：Anchored Standard、MCP Lazy、Minimal Harness、Context/Router 都围绕“模型此刻看到什么”展开。
3. **Anchoring 的判断更成熟了**：不再只看 benchmark/CoT 风格，开始关注 seeding、tool unlock、identity drift、真实 trajectory A/B 与跨模型复现。
4. **Agent Teams 从社区功能进入官方孵化**，社区侧则继续补 staged plan review、可观察拓扑与 durable correctness；多 Agent 的重点从“能并行”变成“可治理、可验证”。
5. **dsh-context 成为高价值观测层**：从单 Session Context Inspector 扩到 Agent Network，并主动适配上游 projection contract 变化。
6. **插件基础设施明显成熟**：dsh-market 从商店演进到冲突处理、诊断、更新 API、精确回滚、真实宿主 E2E；Doctor/Auto Maintenance/Compatibility 形成完整生命周期方向。
7. **0.1.2 是本月最大的上游断点**：alpha.1 引入 Session/API/前端 ABI 大改，alpha.2 又正式进入 npm，插件生态从源码猜测进入可重复迁移验证阶段。
8. **官方开始正面处理插件升级成本**：公开征集 0.1.1→0.1.2 upgrade skill，意味着 compatibility/upgrade tooling 已成为官方认可的开发者体验问题。
9. **Web/TUI/Desktop 开始从“客户端”变成 Runtime**：Side Chat、Subagent Dashboard、TUI plugin API、Remote/Doctor 等能力让交互层本身成为插件承载平台。
10. **当前仍坚持只观察**：官方仍处 Alpha/Developer Preview，Session corruption、插件 ABI、单插件阻断宿主、长期恢复等边界没有稳定到生产级。

### 9 月进入时的优先级
- P0：Anchored / Tool Schema / Context；官方与社区 Agent Teams；Subagent durable correctness。
- P1：0.1.2 alpha.2→RC 兼容窗口；官方 upgrade skill；Market/Doctor/Compatibility；Codex/Claude Provider；TUI/Web/Remote Runtime。
- Candidate：dsh-durable-context、dsh-subagent-contract、dsh-mcp-manager、dsh-auto-maintenance。
