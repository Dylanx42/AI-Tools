## 0.6.3 / Build 21 — 2026-10-23

- 触发：合入前审查发现，已兑换或待处理的券也可能携带未来到期时间，直接按日期统计会误报数量或最近到期。核对 OpenCodex 2.90.0 源码，它还会省略每张券的状态，不能直接要求所有响应都有 `status`。
- 带状态的券只采用 `available`，其余状态不贡献数量和到期时间。可用数量优先采用汇总；无状态日期仅在完整有效列表与汇总一致时展示。不一致时保留数量、将到期时间标为未知；没有汇总时，不从无状态券推算可用数量。兼容用户已验证的 2.90.0 数量与日期响应。
- 维护整理：更新 README 的版本、下载与覆盖安装步骤，记录 Gatekeeper 解除隔离只作用于当前副本、当前尚无 Developer ID / Apple 公证；保留各版本历史验证证据，清理过期开发状态描述。核对 PR #9 已合入 main 且旧分支仍停留在其合并前头提交后，删除遗留远端分支 `fix/codex-quota-trend`。
- 验证：新增 available / redeemed / pending、汇总缺失、无状态列表与汇总一致及不一致的回归。Linux 检查 plist 和 diff；2026-10-23 macOS 14 arm64 的 [CI #61](https://github.com/Dylanx42/AI-Tools/actions/runs/39855573108) 已通过全部离线回归、双架构编译、签名、ZIP 解包权限/签名检查并生成安装包。最新版本仍待 Mac 安装及界面验收，详细项目清单见 README。

## 0.6.2 / Build 20 — 2026-10-23

- 触发：用户确认重置券正常，但 Pro 额度反复显示“OpenCodex 未确认该账户额度的新鲜度”错误。核对 2.90.0 源码，池账户 DTO 本就可能省略可选的 `quotaRefresh`；0.6.1 把缺失元数据误当查询失败。
- 将本地读取成功、上游刷新确认和真正失败分开。缺失或 `not_reported` 时正常更新额度，底部普通标注“上游状态未提供”，不显示橙色错误段落，也不进入失败退避。
- 未确认额度不追加为新趋势点，避免伪造新鲜采样；明确 `ok` 后恢复记录。明确超时/网络错误、重新登录、暂停、缺失窗口和服务错误仍按原逻辑报错。重置券独立查询保留。
- 回归同时发现并修复窗口从有值变为缺失时的 NSNumber 空值比较崩溃，保证部分窗口缺失和恢复时仍能安全记录趋势。
- 验证：新增无元数据/未报告/明确成功/真实失败的映射与状态文案、额度展示更新、退避计数及历史恢复回归。Linux 检查 plist 和 diff；2026-10-23 macOS 14 arm64 的 [CI #57](https://github.com/Dylanx42/AI-Tools/actions/runs/39848023047) 已通过全部离线回归、双架构构建、签名和 ZIP 解包权限/签名检查，源码与修复见 [PR #26](https://github.com/Dylanx42/AI-Tools/pull/26)。用户已在 Mac 验证 0.6.1 重置券更新正常；0.6.2 的本地安装和额度界面仍待验收。

## 0.6.1 / Build 19 — 2026-10-23

- 触发：用户安装 OpenCodex 新版后反馈重置券信息消失；0.6.0 只接入账户列表，遗漏了已有的重置券独立查询。

- 同一 PR 审查修正：账户额度缺少 `quotaRefresh.status=ok` 时视作未确认缓存，不作为新样本写入；补充系统/用户 Applications 中 OpenCodex sidecar 的查找路径。
- 验证：Linux 检查源码和 plist，合成数据覆盖券数量/ISO 到期时间、无数据与零券区别、只读命令参数、异步账户隔离及额度新鲜度。2026-10-23 macOS 14 arm64 的 [CI #51](https://github.com/Dylanx42/AI-Tools/actions/runs/39845115246) 已通过全部离线回归、双架构编译、签名和安装包检查；源码见 [PR #26](https://github.com/Dylanx42/AI-Tools/pull/26)，本地新版安装与真实账户券信息仍待验收。

## 0.6.0 / Build 18 — 2026-10-23

- 触发：用户改为通过 OpenCodex 管理多账户，需要手动选择额度栏监控对象。
- 唯一数据源切换为 `ocx account list openai --quota --refresh --json`，由 CLI 负责认证和服务发现，不再启动官方 app-server。
- 新增「监控账户」子菜单；首次选择当前账户，之后保存明确账户 ID。选择不修改 OpenCodex 实际使用账户；移除已选账户时提示重新选择。
- 使用返回的短/周/月窗口，转换已用比例为剩余比例；缺失窗口显示暂无数据。CLI 未提供的 Credits / 重置券详情不再显示。

- 加入子进程读取期限和输出限制，明确失败/缓存提示；失败缓存不作为新趋势样本写入。
- 构建同时包含 Apple Silicon / Intel 的通用 App；CI 上传保留可执行权限的 ZIP，并检查解包后的权限和签名。
- 验证：用户已在 Mac 的 OpenCodex 2.90.0 上验证查询命令；本次代码在 Linux 开发；2026-10-23 macOS 14 arm64 的 [CI #47](https://github.com/Dylanx42/AI-Tools/actions/runs/39839840770) 已通过 plist、离线回归、双架构编译、签名、ZIP 解包权限与解包后签名检查，并生成安装包。源码见 [PR #26](https://github.com/Dylanx42/AI-Tools/pull/26)。本机新版安装、账户切换、曲线和深浅外观待实机验收。
