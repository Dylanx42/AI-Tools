# 0001 — OpenCodex 账户监控接入

日期：2026-10-23。状态：接受。

用户已通过 OpenCodex 管理账户，希望手动选择独立额度栏的监控对象。原工具仅从默认官方 `app-server` 读取一个登录上下文，无法表达账户池选择。

采用本机 OpenCodex CLI 作为唯一数据源，以 `account list openai --quota --refresh --json` 读取额度。用户在 2.90.0 上已验证该命令。CLI 负责服务发现和认证，避免耦合管理令牌文件格式或自行处理账户凭据；不保留旧 app-server 双数据源模式。

UI 用原生「监控账户」子菜单，首次选择 OpenCodex 报告的当前账户，之后按明确账户 ID 保存。监控与实际路由选择独立，不调用 `account use` 或 `/api/codex-auth/active` 写接口。已保存账户被删除时停止展示并要求重新选择；读取中禁用切换，确保旧请求不会落入新账户历史。

趋势按账户 ID 的 SHA-256 文件名隔离。旧文件没有账户身份，不自动迁移。`__main__` 作为主账户槽位处理；更换登录身份时需备份并移出旧槽位文件，这一限制写入用户文档。其他池账户按 OpenCodex 分配的账户 ID 区分。

只投影 CLI 实际返回的短/周/月窗口。缺失窗口保留未知状态，失败、暂停、需重新登录或明确缓存警告不得产生新趋势样本。读取时间标为 CLI 读取时间，不声称是上游观察时间。账户列表未返回的 Credits 余额不推算。0.6.0 曾遗漏独立重置券查询；0.6.1 改用 2.90.0 已支持的 `account reset-credits <ID> --json` 恢复数量与到期信息，只查询监控账户，不带消费标志，不增加凭据访问。独立失败不阻断额度，切换清空旧数据并以请求代次防止迟到回写。缺少 `quotaRefresh.status=ok` 的额度按未确认缓存处理，不写作新趋势。

整个列表刷新会更新 OpenCodex 额度缓存，其现有路由策略可能使用更新后的额度。额度栏不改路由设置，不主动发推理请求。CLI 升级可能改变 JSON 格式；以离线映射、子进程和历史隔离测试，以及本地实机验收管理兼容性。
